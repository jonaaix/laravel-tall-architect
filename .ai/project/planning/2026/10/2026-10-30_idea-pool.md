# Goal

An always-on guideline that keeps ideas for later in per-area files, so they survive the chat without distracting agents from their task. Done when it ships as a toggleable guideline.

# Milestones

- [x] Agree scope, file layout, entry format and reading rule.
- [x] Add the guideline with config flag, README and tests.
- [x] User reviews the result before push.

# State

Registered after `sidenotes`, on by default. Released in 1.5.0.

# Decisions

- One file per area at `.ai/project/ideapool/<area>.md`. Areas are independent of the Feature Book; a missing area is created, an existing one reused first. No `general.md`, no index — the folder is the index.
- Agents may add their own ideas unless the user rejected them, and must name each addition in their reply so nothing lands unseen.
- Every entry is dated and marked `[user]` or `[agent]` — enough to tell origin when pruning; which agent is irrelevant.
- An idea lives in one place: once it is in a plan, it leaves the pool. A step deferred inside a running feature stays an open milestone in its plan.
- Not read at start, unlike sidenotes: ideas in view on every task cost focus and invite building them on the side. Agents read an area when planning in it, everything when the user asks, and only mention matches.
